## 与 2026-09-24 简历对齐的建议表述

**Gemma Tool-Use：小模型多轮工具调用后训练与受控执行｜独立开发　2026.02–2026.08**

**技术栈：** PyTorch、Transformers、PEFT、QLoRA、SFT、Function Calling。仓库另提供 DPO 流程代码，实际运行与效果需凭原始记录确认。

- 面向多轮任务型对话，将Gemma 3-1B训练为可结合历史上下文与累计状态完成工具调用、缺参追问和直接回复决策的工具调用模型，并生成对应的工具名称和参数；基于CrossWOZ官方语料构建覆盖餐馆、酒店、景点、地铁和出租车5类任务的监督数据，根据每轮用户状态与后续系统查询记录重建训练标签
- 基于Transformers与PEFT搭建SFT训练流程，采用4bit NF4 QLoRA对Gemma 3-1B进行参数高效微调，冻结基座模型并训练LoRA适配器；通过标签掩码仅对目标JSON计算训练损失，使模型统一完成状态更新、调用决策和参数生成
- 设计受控执行链路，将模型输出的状态、调用决策和参数解析为结构化结果，再按工具白名单、字段类型、必填项和风险等级进行校验；缺参时继续追问，有副作用操作转人工确认，避免模型输出直接触发工具执行
- 第二轮 V2 SFT 在训练集内定向重采样难例；固定 440 条 test 上，调用决策准确率由首轮 SFT 的 91.82% 提升至 97.27%，工具选择准确率由 86.93% 提升至 95.17%，参数 Slot F1 由 68.63% 提升至 79.02%。这些数字来自 [V2 评测摘要](../reports/V2_RUN_SUMMARY.md)，不能写成 DPO 的收益。若简历保留“已完成 DPO 训练”的表述，需另找 DPO 训练日志、Adapter 与独立评测记录核对。

## 30 秒介绍

我把 Gemma 3-1B 训练成面向多轮任务型对话的工具调用模型，让它结合历史对话与累计状态判断应调用工具、追问还是直接回复，并生成参数。我将 CrossWOZ 转成结构化监督样本，用 4bit QLoRA 完成首轮 SFT，又针对训练集难例做了第二轮定向 SFT。执行层加入白名单、字段校验和人工确认。在固定 440 条测试样本上，第二轮模型的调用决策准确率为 97.27%，参数 Slot F1 为 79.02%。仓库还实现了 DPO 训练流程，但这两个数字来自 V2 SFT，不能作为 DPO 效果介绍。

## 三个核心追问

1. **训练标签如何构造？** 将每个用户轮转换为训练样本，保留历史对话、上一轮累计状态、当前请求和工具定义，并依据用户状态及后续系统数据库查询重建调用决策、工具名称和参数
2. **DPO 流程如何设计，目前验证到哪一步？** 代码在同一训练 Prompt 下把标准 JSON 作为偏好响应，把 SFT 模型真实错误作为非偏好响应；公开仓库尚无可复核的 DPO 效果报告，不用 V2 SFT 数字代替
3. **三个指标分别说明什么？** 调用决策准确率衡量该调用、追问还是停止；工具选择准确率衡量决定调用后是否选对工具；参数槽位 F1 衡量参数键值的整体匹配质量

## 表述边界

- 不称为生产系统或真实外部业务接口；工具执行为本地可复现演示
- CrossWOZ 是对话语料，工具调用标签由用户状态和系统查询记录转换而来，不是官方原生 Function Calling 数据
- 参数槽位 F1 不等于完整工具调用成功率；复杂多参数生成仍是主要短板
- challenge 是项目内固定切片，不冒充 BFCL 等外部基准
- V2 的 97.27% 决策准确率、79.02% 参数 Slot F1 来自定向重采样的第二轮 SFT；DPO 效果须用单独的训练与评测记录证明

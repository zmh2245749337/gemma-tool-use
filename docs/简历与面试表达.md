# 简历与面试表达

## 推荐项目名

**Gemma 3-1B：Agent 工具调用微调与受控执行框架**

这个标题先说明交付物，再补模型名。它比“Gemma 多轮工具调用”更像完整系统，也不会夸成生产平台。

## 简历版本

### 项目简介

面向任务型 Agent 构建小模型 Tool-Use 后训练与可靠性验证框架，覆盖多轮训练数据构造、4bit QLoRA、结构化决策协议、受控工具运行时及错误驱动的第二轮训练。

### 项目要点

- 面向小参数模型在多轮工具调用中容易出现上下文状态遗失、工具误选和参数缺漏的问题，基于 Gemma 3-1B 构建工具决策模型，使其完成调用工具、缺参追问或无需调用的决策，并生成对应工具名称与参数。
- 基于 CrossWOZ 官方数据构建多轮工具调用训练集，按照用户轮提取历史对话、上一轮状态、当前请求和候选工具，并依据用户状态与系统数据库查询标注生成监督标签。
- 基于 Transformers 与 PEFT 搭建 SFT 训练流程，采用 4bit NF4 QLoRA 微调 Gemma 3-1B，在注意力层和前馈网络中注入 LoRA 适配器，冻结基座参数并仅计算目标 JSON 部分的训练损失。
- 构建模型输出校验与受控执行链路，模型生成对话状态、调用决策和参数后，由运行时校验工具白名单、参数类型及必填字段；只读查询可自动执行，有副作用操作需人工确认。
- 基于首轮失败样本开展第二轮定向训练；固定 test 上工具选择准确率由 86.93% 提升至 95.17%，参数 Slot F1 由 68.63% 提升至 79.02%，非工具轮误调用率由 11.36% 降至 3.41%。

## 30 秒介绍

这个项目解决的是 Agent 里靠近模型的一层：小模型怎样在多轮对话中维护状态、正确选择工具并生成参数，以及代码怎样约束模型不能直接获得执行权限。我把 CrossWOZ 转换为多轮工具调用监督数据，用 4bit QLoRA 微调 Gemma 3-1B，再根据首轮失败样本进行训练集内定向重采样。固定 test 上工具选择由 86.93% 提升至 95.17%，参数 Slot F1 由 68.63% 提升至 79.02%，非工具轮误调用率降至 3.41%。

## 3 分钟主线

1. **问题**：API 大模型通常能做 Function Calling，但小模型在多轮状态、格式遵循和何时不调用上不稳定；而模型输出不能直接获得执行权限。
2. **数据**：把 CrossWOZ 每个用户轮转换成 history、previous state、current user 和目标决策，并统一为 Agent Trace；对自然数据不足的缺参场景做 split 内单槽位消融并显式标记。
3. **训练**：Gemma 3-1B 以 4bit NF4 加载，使用 LoRA r16；只训练目标 JSON，保留 Base 作为同设置对照。
4. **运行时**：模型输出 belief state、call/ask/no-tool、工具与参数；代码做 Schema、白名单、必填参数和风险校验，副作用工具必须人工确认。
5. **评测**：不仅看工具准确率，还看 JSON、Schema、状态 JGA/F1、参数 exact/F1、误调用率，并对指代、修正、跨领域和长状态切片。
6. **结果与不足**：V2 的工具选择、参数 Slot F1 和停止判断均有提升；参数完全匹配仍为 42.61%，复杂参数精确生成仍是主要短板。

## 面试中不要说

- 不说“企业级”“生产可用”“真实派车”；
- 不说“复现 BFCL”，只能说评测分层受 BFCL/When2Call 启发；
- 不把 92.96% Slot F1 说成状态完全正确率，V2 test 的 JGA 是 60.00%；
- 不说支持多工具并行或完整规划，当前每轮选择一个工具；
- 不把受控消融说成 CrossWOZ 原生样本；
- 不把 LoRA 说成训练了 Gemma 全部参数。

## 最容易被追问的五个点

1. 为什么 Prompt token 不算 loss？
2. JGA 和 Slot F1 为什么差这么多？
3. 为什么风险不能让模型自己判断？
4. Base 的误调用率 0% 为什么不是更安全？
5. 参数 Exact Match 只有 42.61%，下一步怎么改？

这些问题都能从仓库代码和自动报告中找到证据，回答重点是“设计原因—实现位置—指标结果—真实边界”。
